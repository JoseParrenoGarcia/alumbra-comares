# M30 — Frontend Regression Tests

## Goal

Add a focused test layer that protects the most important static-site behavior after the simplification refactor.

## Recommended Delivery Mode

- Lead: Codex Sonnet or stronger
- Haiku may help add repetitive test cases once the harness and strategy are chosen

## Dependencies

- M29 complete

## PR Scope

- Test setup and config
- Tests for critical HTML, JS, and content-loading behavior
- Minimal production-code changes only if needed to make behavior testable

## Tasks

- [ ] Choose the lightest test approach that fits the project
- [ ] Cover high-value behaviors first:
  content loading, language switching, nav interaction, metadata updates, and contact form wiring assumptions
- [ ] Prefer stable tests over broad but brittle coverage
- [ ] Avoid snapshot-heavy tests that will be noisy for content edits
- [ ] Document how to run the tests in `README.md`

## Definition of Done

- The project has a practical regression suite for the core behaviors
- Tests are easy to run locally
- The chosen approach matches the project’s lightweight philosophy

## Open Questions

- Do we want browser-level tests, DOM-level tests, or a very small mix of both?
