# M14 — Persona Audit Framework

## Goal

Create a reusable set of personas and an audit rubric so the site can be reviewed consistently as content and structure evolve.

## Recommended Delivery Mode

- Lead: human-led research plus Codex Sonnet consolidation
- Support: Haiku may help format the final rubric once the personas are approved

## Dependencies

- M12 complete
- M13 strongly recommended first

## PR Scope

- `docs/research/m14-personas.md` — approved persona set
- `docs/research/m14-audit-rubric.md` — repeatable evaluation template
- `docs/PRD.md` — optional audience clarification if needed

## Tasks

- [ ] Define 4–6 personas grounded in likely real visitors, not marketing stereotypes
- [ ] Include for each persona:
  situation, needs, anxieties, questions, trust triggers, and likely next action
- [ ] Include at least:
  first-time parent, parent comparing care options, event-curious visitor, referral-based visitor
- [ ] Turn the personas into a repeatable audit rubric with scored criteria
- [ ] Ensure the rubric can be reused after future milestones without rewriting it
- [ ] Keep the framework practical; avoid fictional backstories that do not affect site decisions

## Human Research Prompt

```text
Help me define realistic personas for a small independent midwife collective website in Valencia, Spain.

Context:
- The brand should feel warm, calm, human, and community-led
- The site is for prospective pregnant families, not for a hospital system
- Current and future site decisions include service explanations, contact channels, trust signals, events, resources, and possible multi-page expansion

Please produce:
1. 4–6 realistic personas
2. For each persona:
   - short label
   - context / situation
   - what they are trying to decide
   - what they need from the website
   - what could confuse or worry them
   - what would build trust
   - preferred contact behavior
3. A reusable website audit rubric based on those personas, with 6–10 criteria and a simple scoring method

Keep it realistic for Spain and avoid corporate UX jargon.
```

## Definition of Done

- The project has a reusable persona pack and audit rubric
- Later audits can reference the same personas without inventing new ones
- The persona set helps make clearer choices about copy, IA, and contact patterns

## Open Questions

- Should one persona explicitly represent a partner or co-parent rather than the pregnant person?
- Should we include one low-digital-confidence persona for accessibility and clarity checks?
