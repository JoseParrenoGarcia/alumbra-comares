# M25 — English Rollout

## Goal

Ship English as a real supported language, not just a placeholder in the content schema.

## Recommended Delivery Mode

- Lead: Codex Sonnet or stronger for i18n implementation and content QA
- Support: Haiku may help with repetitive translation field wiring after the architecture is defined

## Dependencies

- M20 complete
- M24 recommended first so legal copy does not get translated twice

## PR Scope

- All `content/*.json` files that contain user-facing Spanish copy
- `index.html`, legal pages, nav handling, and any shared JS needed for language switching
- Minimal CSS updates only if the switcher or layout requires them

## Tasks

- [ ] Populate `en` fields across all content JSON used at runtime
- [ ] Replace the visual-only language toggle with a functional switcher
- [ ] Persist language state in a simple, transparent way suitable for a static site
- [ ] Update `<html lang>` correctly per language
- [ ] Ensure legal pages participate in the language system or clearly remain Spanish-only with an explicit note
- [ ] Do not mix hardcoded translated strings into HTML

## Definition of Done

- A user can switch between Spanish and English without broken content
- Content, nav labels, and core metadata update correctly
- The language system remains simple enough for a static site

## Open Questions

- Should English become URL-addressable later, or is in-page switching enough for now?
