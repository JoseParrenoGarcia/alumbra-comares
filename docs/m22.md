# M22 — Asset Readiness and Media Audit

## Goal

Prepare the project’s visual assets so images and media are ready for broader rollout: selected intentionally, optimized for the web, clearly sourced, and described accessibly.

## Recommended Delivery Mode

- Lead: Codex Sonnet or stronger
- Human review required for image choice, source confirmation, and usage rights
- Haiku can help with mechanical file moves or markup wiring after decisions are made

## Dependencies

- M17 complete
- M18 and M19 recommended

## PR Scope

- `assets/images/`
- `docs/assets.md`
- Relevant `content/*.json` files if asset references move into content
- Minimal HTML/CSS updates only if asset structure changes require them

## Tasks

- [ ] Inventory all current and planned visual assets:
  portraits, decorative graphics, brochure/resource imagery, and social share imagery
- [ ] Define source-of-truth rules for each asset:
  filename, purpose, owner/source, rights status, and target usage
- [ ] Optimize selected assets for web delivery with sensible file sizes and dimensions
- [ ] Add or define alt-text conventions for content-bearing images
- [ ] Define how decorative images are identified and hidden from assistive tech
- [ ] Decide whether a default social share image should be prepared now for SEO metadata
- [ ] Avoid introducing asset-management tooling that is heavier than the project needs

## Definition of Done

- The project has a clear asset inventory and handling rules
- Image usage is easier to maintain and less likely to drift into ad hoc files
- The site is better prepared for SEO, accessibility, and multilingual rollout

## Open Questions

- Are founder portraits and other real images already approved for web use, or do we still need a separate content handoff?
