# M21 — Content Governance System

## Goal

Create a lightweight editorial and content-operations system so future copy, translation, placeholder cleanup, and schema changes stay consistent across the site.

## Recommended Delivery Mode

- Lead: Codex Sonnet or stronger
- Haiku can implement documentation updates once the conventions are defined

## Dependencies

- M15 complete
- M17 recommended
- M20 recommended

## PR Scope

- `docs/content-governance.md`
- `docs/playbook.md`
- `content/` conventions only if minor schema normalization is required

## Tasks

- [ ] Define canonical rules for content JSON structure:
  translation fields, arrays, IDs, placeholders, optional fields, and metadata fields
- [ ] Define placeholder lifecycle rules:
  how placeholders are marked, reviewed, approved, and removed
- [ ] Define how new sections or pages should introduce content files without breaking consistency
- [ ] Define a lightweight workflow for copy changes, translation updates, and founder review
- [ ] Add a short approval checklist for content PRs
- [ ] Keep the system small and practical; no CMS or heavyweight process

## Definition of Done

- A smaller implementation agent can update content safely by following one document
- Content structure drift is less likely as the site grows
- The governance rules fit the project’s lightweight philosophy

## Open Questions

- Should governance rules live mostly in one new doc, or be split between `docs/playbook.md` and a dedicated content guide?
