Clean up accumulated debt in HTML, CSS, and JS without changing any user-facing behavior. The product surface is stable — this is the right window before M30 (tests) and M31 (framework decision).

- Haiku should not run this milestone without a strong review pass

## Tasks (in execution order)

### Task 1 — Inventory and dead-code removal in `content-loader.js`

**File:** `js/content-loader.js`

Before touching anything else, establish what is still live:

- Read every function defined in `content-loader.js`
- Identify any functions not called from the `DOMContentLoaded` init dispatcher or from other live functions
- Delete only functions that are verifiably unreachable (no caller anywhere in the codebase)
- Audit the `sections/` directory: any `.html` partials that are no longer fetched by `content-loader.js` or any other JS should be listed in the PR notes and deleted if confirmed orphaned
- After dead code is removed, reorganize remaining functions into 5 labeled sections with divider comments:

```
// ── Utilities ──────────────────────────────────────────────────────
// loadJSON, loadSection, channelIcon, getFriendlyPlaceholder,
// getFriendlyAnswer, renderFriendlyAnswer, revealSection

// ── Page detection ─────────────────────────────────────────────────
// isHomepage, isFaqPage, isComoTrabajamosPage, isRecursosPage,
// isFormacionPage, isEventosPage, isServiciosPage

// ── Homepage section populators ────────────────────────────────────
// (all functions used only on the homepage)

// ── Standalone page populators ─────────────────────────────────────
// (all functions used only on standalone pages)

// ── Init ────────────────────────────────────────────────────────────
// DOMContentLoaded dispatcher
```

Also document in PR notes: the `reveal.js` / `content-loader.js` coupling (`revealSection()` is called manually from populators because `reveal.js` only observes on DOMContentLoaded before dynamic content exists). This is known debt, not fixed in M29.

**Expected result:** Smaller, organized file. Dead paths gone.

### Task 2 — Remove duplicate `.reveal` CSS

**Files:** `css/brochure.css`, `css/events.css`, `css/formacion.css`, `css/how-we-work.css`, `css/recursos.css`, `css/services.css`, `css/testimonials.css`

The base `.reveal`, `.reveal.visible`, and `@media (prefers-reduced-motion)` rules are defined once in `css/utilities.css` and apply to all `.reveal` elements globally.

In each component file, delete only blocks that are byte-for-byte identical to the utilities.css base rules. Do **not** delete component-specific variations such as stagger delays, custom transition durations, or hover-related overrides — keep anything that differs from the base.

Pattern to delete (and only this pattern):
```css
.{anything}.reveal { opacity: 0; transform: translateY(...); transition: opacity var(--transition-gentle), transform var(--transition-gentle); }
.{anything}.reveal.visible { opacity: 1; transform: translateY(0); }
@media (prefers-reduced-motion: reduce) { .{anything}.reveal { opacity: 1; transform: none; transition: none; } }
```

**Expected result:** ~168 lines removed. Zero visual change. Verify by checking all reveal animations still fire after deletion.

### Task 3 — Nav centralization via `nav.js`

**Files:** `js/nav.js` + 7 HTML files + `privacidad.html` + `cookies.html`

The same 61-line nav block is copy-pasted across 7 pages. Centralize it.

**In `nav.js`:**

Define two explicit nav HTML constants at the top of the file:

- `SUBPAGE_NAV_HTML` — uses `index.html#hash` anchors (correct for all non-homepage pages)
- The homepage nav (`index.html`) stays static — do not touch it

Add `injectNav()` as the first call inside `DOMContentLoaded`. It reads a `data-nav` attribute on the placeholder to know which variant to inject (only one variant exists for now: `subpage`), then writes the HTML and returns. All existing scroll/toggle/overlay event listeners run after injection.

```html
<!-- placeholder in subpages -->
<nav class="nav" id="main-nav" data-nav="subpage"></nav>
```

**HTML files to update** (replace full `<nav>` block with placeholder):
- `eventos.html`, `servicios.html`, `formacion.html`, `recursos.html`, `como-trabajamos.html`, `faq.html`, `404.html`

**`privacidad.html` and `cookies.html`:** Do not template these. They use a simpler nav (no dropdowns). However, audit their nav links for stale anchors — specifically `index.html#eventos` which no longer resolves to a homepage section. Fix any stale links in-place.

**Leave unchanged:** `index.html` (unique same-page anchors).

**Expected result:** 7 HTML files each lose ~58 lines. Nav markup has one source of truth. Legal pages have correct links.

## What We Are NOT Doing

- **`.page-cta` injection** — 5 lines × 6 files is not worth adding more responsibility to `content-loader.js`. Leave as-is.
- **Footer extraction** — Footer renders without JS. Silent failure risk outweighs the benefit.
- **CSS file consolidation** — 22 files 1:1 with components is organized. Don't merge.
- **ES modules / build tooling** — No build step. That decision is M31.
- **`?v=2` query strings** — Not broken. Keep them.
- **Legacy content JSON cleanup** — If a JSON file looks unused, inventory it in PR notes but do not delete it in M29 unless its removal is proven safe and explicitly reviewed as part of this milestone.

## Final Review

### Shared conclusions from Sonnet plan + Codex audit

- **Proceed with CSS simplification** by removing only byte-identical duplicate `.reveal` rules and preserving any component-specific stagger, delay, or reduced-motion overrides.
- **Proceed with `content-loader.js` cleanup** as both a structural reorganization and a dead-code pass. Reordering alone is not enough.
- **Proceed with nav centralization** for the 7 duplicated subpage navs. Keep `index.html` static because it uses same-page `#hash` anchors. Keep legal pages static, but audit and fix their stale links in-place.
- **Do not centralize the repeated `.page-cta` block** in M29. The duplication is too small to justify adding more JS indirection.
- **Document but do not solve** the current `reveal.js` / `content-loader.js` coupling in this milestone.
- **Treat orphaned partials and legacy content files conservatively**: remove dead code and clearly orphaned section partials, but only inventory suspicious legacy JSON unless deletion is fully verified.

### Final readiness verdict

**Yes** — this milestone is ready to implement.

Why yes:

- The scope is now narrow and behavior-preserving.
- The highest-value simplifications are explicit.
- The main disagreement from the earlier draft (`.page-cta` injection) has been resolved out of scope.
- The remaining risk areas are named with guard-rails instead of being left implicit.
