# M29 — Simplification Refactor

## Goal

Audit the codebase for unnecessary complexity and refactor toward a simpler, clearer static-site architecture without changing the approved user-facing behavior.

## Recommended Delivery Mode

- Lead: Codex Sonnet or stronger
- Haiku should not run this milestone without a strong review pass

## Dependencies

- M18 through M28 complete, or at least the currently planned product surface is stable enough

## PR Scope

- HTML, CSS, JS, and content-loading code as needed
- No content expansion and no new features unless required to simplify the existing implementation

## Tasks

- [ ] Audit for duplication, brittle selectors, unnecessary JS, and avoidable coupling
- [ ] Prioritize simplicity over cleverness
- [ ] Preserve the JSON-driven content rules and established style system
- [ ] Refactor in small reviewable steps:
  content loading, language handling, navigation behavior, metadata handling, CSS organization
- [ ] Document any non-obvious architectural simplification in the PR notes
- [ ] Do not convert frameworks or introduce build tooling in this milestone

## Definition of Done

- The codebase is easier to understand and maintain
- Existing behavior still works
- The refactor reduces complexity rather than moving it around

## Open Questions

- Are there any parts of the current architecture that should be left imperfect until after M31?
