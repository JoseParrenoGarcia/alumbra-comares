# M18 — Education and Credentials Section

## Goal

Add a trust-building section or page that communicates the team’s professional credibility in layers: registration numbers, insurance confirmation, languages spoken, specialist credentials, and formal training history. The benchmark research (M13) found that no single trust signal is sufficient — visitors need the full stack before they feel safe choosing an independent practice.

The tone must remain warm and specific, not bureaucratic.

## Recommended Delivery Mode

- Lead: Haiku build pass is acceptable if the IA decision from M17 is already clear
- Review: Sonnet review pass for tone, schema quality, and scope discipline

## Dependencies

- M17 complete

## PR Scope

- `content/education.json`
- One of:
  `sections/formacion.html` or a new dedicated page if M17 recommends it
- Supporting CSS and minimal JS only if required by the chosen layout
- `content/site.json` and nav/footer content only if a new entry is needed

## Tasks

- [ ] Define the credential content schema before writing markup
- [ ] Schema must support per-member fields: registration number, professional body, insurance status, languages spoken, degree, certifications, courses, training, affiliations, year — all with placeholder flags
- [ ] Populate only confirmed items from `assets/reference-docs/reference-content-in-text.md`; explicit placeholders everywhere else
- [ ] Structured fields to add to `content/team.json` per member:
  `registration`, `insurance`, `languages`, `credentials` (array), `training` (array)
- [ ] Present the trust layer visually integrated near the midwife profile section, not as a dry standalone appendix
- [ ] Keep the tone confidence-building: "trained in Spain and the UK, registered midwife, insured" reads better than a formal CV block
- [ ] Follow the IA decision from M17 exactly; do not invent new nav structure

## Definition of Done

- Each midwife card carries at minimum a registration placeholder, languages spoken, and one credential
- The full credential schema is present in `content/team.json` even where values are `__PLACEHOLDER__`
- Result increases trust without feeling institutional
- Unknowns remain visible and clearly marked
