# M27 — Accessibility Audit and Remediation

## Goal

Run a focused accessibility pass on the mature site and fix the most important issues affecting keyboard use, screen-reader comprehension, motion sensitivity, and readable contrast.

## Recommended Delivery Mode

- Lead: Codex Sonnet or stronger
- Human verification recommended for manual keyboard and reading-order checks
- Haiku can help apply contained fixes after the audit findings are clear

## Dependencies

- M25 complete
- M26 recommended

## PR Scope

- HTML, CSS, and JS files that need accessibility fixes
- Optional short audit note in `docs/research/m27-accessibility-audit.md`
- `docs/playbook.md` only if new accessibility guardrails should be added

## Tasks

- [ ] Audit heading hierarchy, landmark structure, and page titles
- [ ] Audit keyboard navigation:
  nav, language switcher, links, buttons, forms, and any mobile menu behavior
- [ ] Audit focus visibility and focus order
- [ ] Audit reduced-motion behavior and any reveal effects
- [ ] Audit color contrast for text, placeholders, buttons, and muted states
- [ ] Audit image alt text and decorative image handling
- [ ] Fix the highest-value issues without redesigning the site

## Definition of Done

- Core site paths are usable by keyboard
- The most important semantic and motion issues are resolved
- The project has a clearer baseline for future content and page additions

## Open Questions

- Should this milestone aim only for practical remediation, or should it also target a named WCAG level later?
