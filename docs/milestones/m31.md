# M31 — React Migration Audit

## Goal

Make an explicit recommendation on whether the project should remain static HTML/CSS/JS or migrate to React for the next major phase.

## Recommended Delivery Mode

- Lead: human + Codex Sonnet synthesis, optionally with external model comparisons
- Not Haiku-led: this is an architectural decision, not an implementation task

## Dependencies

- M29 complete
- M30 strongly recommended

## PR Scope

- `docs/research/m31-react-audit.md`
- `docs/PRD.md` only if the long-term platform recommendation changes

## Tasks

- [ ] Audit the current codebase after simplification and tests
- [ ] Evaluate real reasons to migrate:
  content complexity, routing needs, localization complexity, testing ergonomics, and future contributor workflow
- [ ] Evaluate real reasons to stay static:
  simplicity, hosting ease, low runtime complexity, and small-team maintenance
- [ ] Compare at least three paths:
  stay static, add a light static-site toolchain, or migrate to React
- [ ] End with a recommendation, not just a pros/cons list
- [ ] Do not begin a migration in this milestone

## Human Review Prompt

```text
Help me evaluate whether a small multilingual static website should stay on HTML/CSS/JS or migrate to React.

Context:
- currently static site hosted simply
- JSON-driven content
- likely multiple languages
- modest interactive behavior
- possible future resources/blog and a few extra pages
- small team, low maintenance preference

Please provide:
1. Decision criteria
2. Reasons to stay static
3. Reasons to adopt a light static-site toolchain instead of React
4. Reasons to migrate to React
5. Warning signs that React would be premature
6. A recommendation framework for a small project like this

Distinguish general advice from assumptions about this project.
```

## Definition of Done

- The project has a clear recommendation on architecture direction
- The recommendation is grounded in the actual codebase and roadmap
- No migration work begins until this audit is reviewed

## Open Questions

- Would a future CMS requirement change this recommendation more than current interactivity needs?
