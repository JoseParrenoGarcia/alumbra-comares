# M14B — Site Scoring Skill

## Goal

Build a reusable Claude Code skill that scores any iteration of the Alumbra Comares site against the full persona pack and the best-practice canvas. The skill should be runnable after any build milestone to produce a structured scorecard without needing to re-explain context each time.

## Why this follows M14

M14 produced a persona pack (13 personas) and an audit rubric (10 criteria). That rubric was written before the persona set grew to 13. It covers only a subset of what the best-practice canvas defines. This milestone closes both gaps and makes the output executable rather than a static document.

## Dependencies

- M13 complete (canvas available at `docs/research/Alumbra_Comares_Best_Practice_Canvas.md`)
- M14 complete (personas at `docs/research/m14-personas.md`, rubric at `docs/research/m14-audit-rubric.md`)

## PR Scope

- `.claude/skills/score-site/SKILL.md` — the executable scoring skill
- `.claude/skills/score-site/references/` — pointers and lookup material loaded on demand (see below)
- `docs/research/m14-audit-rubric.md` — updated to cover all 13 personas and all canvas dimensions

## What is missing from the current rubric

The existing rubric has 10 criteria. It was written for 6 personas before the canvas was fully synthesised. The following are not scored anywhere:

### Missing persona coverage

- **P7 — First-time home birth**: Is home birth mentioned explicitly as a service? Is transfer protocol visible?
- **P8 — Repeat home birth**: Is team home birth experience indicated (number of births attended)?
- **P9 — Traumatic prior birth**: Is birth autonomy / advocacy language present? Is birth plan preparation offered?
- **P10 — English-speaking expat**: Is an English-language signal present (team bios, page, or at minimum "hablamos inglés")?
- **P11 — Expat from midwife-led system**: Is continuity of care explained? Is home birth scope explicit?
- **P12 — Influential family member / sceptic**: Are credentials and registration readable without prior knowledge of midwifery? Is complementary-to-hospital framing present?
- **P13 — Professional referrer**: Are registration numbers visible? Is scope of practice defined? Is insurance mentioned?

### Missing canvas dimensions

From `docs/research/Alumbra_Comares_Best_Practice_Canvas.md`:

- **Trust layer: professional legitimacy** (section 5) — colegiada numbers, insurance, affiliations
- **Trust layer: experience** (section 5) — years, number of families, types of care
- **Trust layer: safety and boundaries** (section 5) — eligibility, transfer plan, out-of-hours, role limits
- **Trust layer: practical transparency** (section 5) — pricing signal, session length, follow-up window
- **Service architecture: life-stage routing** (section 4) — can a visitor arrive at "I just had a baby" and find the right thing without reading everything?
- **Service architecture: home birth scope** (section 4) — is home birth surfaced as an explicit service option with scope described?
- **IA: homepage narrative sequence** (section 3) — does the page follow hero → pathways → philosophy → team → first contact → trust layer → CTA?
- **Contact: WhatsApp Business** (section 6) — is a dedicated WhatsApp CTA present, not a personal number?
- **Contact: free intro call** (section 6) — is a no-commitment first meeting offered?
- **Pitfall check: solo-voice trap** (section 9) — does the site read as a collective, not one founder?
- **Pitfall check: pricing opacity** (section 9) — is there any pricing signal?
- **Pitfall check: role ambiguity** (section 9) — are role boundaries clear if non-midwife roles appear?
- **Tone: competent tenderness** (section 8) — is copy warm but grounded, not vague-mystical or clinical?

  - Keep the 0/1/2 scoring method; adjust the total accordingly

  - Output format template: a markdown table with criterion, score (0/1/2), and one-line finding per row, plus a total and a prioritised list of the three lowest-scoring areas
  - Gotchas section: e.g. placeholders in content JSON count as missing, not partial; HTML structure is not enough if JSON content is `__PLACEHOLDER__`

## Open Questions

These are for the executing agent to resolve by reading the codebase and making a judgment call. Document the decision in the PR.

- Should the skill also check for specific HTML patterns (e.g. WhatsApp link format `wa.me/`, `aria-label` presence) or only content JSON? Checking both gives more signal but requires the skill to read more files.
- Should the skill produce a diff-style comparison between two runs (e.g. post-M15 vs. post-M18), or is a standalone snapshot sufficient for now?
- Should the scoring output be written to a file (e.g. `docs/research/scores/YYYY-MM-DD.md`) for historical comparison, or only printed to the terminal?

## Definition of Done

- The site can be scored at any point by invoking the skill without providing additional context
- The rubric covers all 13 personas and all identified canvas dimensions
- The scorecard output is a structured markdown table with criterion, score, and finding per row
- The skill file is under 500 lines and passes the create-skill anti-pattern checklist
- One smoke-test scorecard run is included in the PR description
